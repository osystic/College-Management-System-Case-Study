# Engineering lessons

1. **Role isolation must be demonstrated:** a correct page for an administrator is not enough; denied student/faculty access is part of acceptance.
2. **Translation needs exhaustive inventories:** one language toggle is insufficient; labels, form feedback, RTL spacing and dynamic data boundaries all need tests.
3. **Schema and code deploy as a coordinated change:** a safe database migration must precede code that depends on new columns.
4. **Avoid pretending adapters are live integrations:** a production provider requires keys, callbacks, error handling and business authorization.
5. **Keep public stories separated from source history:** anonymized capability proof should not accidentally expose private data or the client.
6. **Technical checks are not client acceptance:** formal academic policies and human review remain separate from passing automated tests.
