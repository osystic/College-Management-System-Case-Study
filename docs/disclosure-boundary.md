# Public/private disclosure boundary

| Information | Public case study | Confidential delivery |
|---|---|---|
| Generalized system architecture | Yes | Yes |
| Technical design patterns | Yes | Yes |
| Source code and SQL schema | No | Yes, restricted |
| Student/faculty or applicant records | No | Controlled by institution |
| Public site or internal production endpoints | No | Restricted operations |
| API keys, payment and email credentials | No | Secrets management only |
| Institution identity and private correspondence | No | Restricted |
| Screenshots and branded UI | No | Review under client permission |
| Commercial terms / contract data | No | Confidential |
| Technical test methodology | Yes | Yes |
| Operational backup and access details | No | Restricted |

**Public repository history is independent:** never fork or mirror the confidential source. Do not add private screenshots, datasets or client names later merely because the page is already public.
